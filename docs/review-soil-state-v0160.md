## 待主分身修正的具體發現

### P1：D17負摩擦結果被標成「單樁極限壓力」

位置：`site/studio/models.js:75`；土壤 `soil-foundations-d17-v2`。

- D＝0.792 m、L＝15 m、fs＝50 kPa、qb＝3000 kPa。
- Qb＝1477.955980696 kN；Qdrag＝1866.106036232 kN；Qb−Qdrag＝−388.150055536 kN。
- 算術正確，但輸出標籤「題設單樁極限壓力」及既有步驟未說明負號代表抵抗不足。負值不能被當成可承受的壓力容量。
- 建議改稱「端承扣除負摩擦的有號餘額」，並明示負值為缺額、無可加外壓力；若保留作為診斷題，這比掩去負值更有教學價值。
- 新回歸第二條目前確實失敗；`node --test tests/studio-soil-review.test.js`：2項、1通過、1失敗、exit 1。失敗訊息為標籤不符合 `/有號|餘額|缺額|不足/`，不是數值錯誤。

### P2：開啟錯因提示前沒有固定首次數值

位置：`site/studio/app.js:65`；對照完整詳解第64行及 `state.js:27` 的 `freezeInitial()`。

目前流程：先填錯值 → 開錯因解答（只將 hint 設2）→ 改成正確值 → 首次提交（第62行才固定 firstValues）。結果首答會成為提示後修正值。這與完整詳解開啟時立即保存 firstValues 的行為不一致。

建議：錯因解答開啟時，先 capture 並 freezeInitial，再設定協助與顯示答案；保持首次、修正、協助層級都可回讀。

### P2：歷史頁僅顯示首次數值，沒有並列最後提交值

位置：`site/studio/app.js:55`。

JSON 中 `record.values` 及 `assessment.checks.actual` 仍保有提交值；畫面只列 `firstValues ?? r.values`。當首答及訂正不同時，使用者無法在歷史頁直接核對本次最後的數值。建議並列「首次數值」與「本次提交數值」，不改歷史原稿。

### P2：提交儲存失敗後仍顯示原稿已保留

位置：`site/studio/app.js:62`。

`persist()` 回傳 false 後仍顯示成功語氣、禁用提交，並呼叫 `cloud.submitted()`。頂端已有儲存警告，記憶體仍可匯出，故本次不主張已發生資料遺失；但不能把未落盤說成完成保存。

建議依回傳值顯示「未成功儲存，請立即匯出」，保留目前記憶體紀錄，避免誤認持久化成功；自動雲端提交提示只在本機保存成功後執行。

## 已明示的模型限制

- D04目前演練均質定常Darcy，不涵蓋變水頭、串並聯分層透水係數全部課題。
- D11只檢查排水包絡線；D12～D13只檢查題給孔壓的主應力換算，沒有完整UU/CU/CD試驗判釋或應力路徑推導。
- D15、D24使用D＝0、c＝0條基礎題給Nγ的簡化模型；未計沉陷或法規完整支承力。
- D16限全接觸單向偏心；D20只檢滑動；D21只檢上舉；D22只檢無凝聚力無限邊坡；D23的CRR、CSR、MSF均題給，不是SPT/CPT液化判定程序。
- D24～D27原卷與自編題的對應只保留課題標籤，本次未取得官方原卷逐題數值核對，不能宣稱已完成官方原卷詳解驗證。
